ESTUDO DE CASO • 2026

Como testar um sistema antes de colocar em produção?

Um laboratório de clientes fictícios, pré-notas e testes automatizados, baseado em um cenário de gestão da LD Engenharia.

Nenhuma nota fiscal real foi emitida. Tudo é simulado em banco local, sem acessar a plataforma da empresa.

Uma tela funcionando não prova que o sistema está correto.

ARQUITETURA

Uma aplicação Full Stack, sem dependência paga

🌐 Interface HTML/JS→⚙️ API Node.js→🗃️ SQLite
A API aplica validações, transações, chave idempotente e vínculo entre cliente e documento. O banco local permanece salvo após reiniciar o sistema. O backend atende só em 127.0.0.1.
DEMONSTRAÇÃO

Primeiro, mostramos o fluxo real do laboratório

Cliente fictício→Pré-nota simulada→Persistência→Métricas
npm start

Abra http://127.0.0.1:8787, gere clientes e crie documentos. Recarregue a página e confira os dados persistidos.

REGRAS / TESTES

Comportamento esperado e falhas controladas

201 — documento criado
200 — mesma chave e conteúdo, sem duplicar
409 — mesma chave com valor diferente
400 — valor ou quantidade inválida
404 — cliente inexistente
0 — documentos fiscais reais emitidos
npm test
